## Windows 便携版：无需安装环境

适用于 Windows 10/11 x64。到 [Releases](https://github.com/MewzCC/KleeAPI/releases) 下载 `KleeAPI-版本号-windows-x64.zip`；`Source code (zip)` 和仓库的 `Code → Download ZIP` 是源码包。发布附件上传后才会出现在 Releases；也可从成功的「Windows portable release」Actions 构建记录下载成品（需要 GitHub 登录，先解开 Actions 外层附件）。

1. 对正式发布 ZIP 点击右键 →「全部解压」，选择桌面或自己的用户文件夹。
2. 打开解压出的 `KleeAPI-版本号-windows-x64` 文件夹，双击 `Start-Manager.cmd`。
3. 检查通过后浏览器自动打开。直接从下面的「4. 添加一个你自己的平台账号」继续操作。
4. 使用结束，双击 `Stop-Manager.cmd`。关闭浏览器不会停止后台服务。

便携版包含固定版本 Node.js LTS、编译后的页面及 Qoder 官方组件，不需要安装 Node、npm，也不需要运行下面的源码构建命令。启动不需要管理员权限；登录、签到和模型调用仍需联网。第一次启动会在本机创建全新的 Key 和账号存储。

不要直接在压缩包内双击脚本。如果提示文件缺失或完整性校验失败，请重新完整解压；如果提示端口占用，先停止自己已启动的 KleeAPI，或修改 `klee-config.json` 中的端口。启动失败的窗口会保留错误提示，详细日志在 `runtime/logs/`。

下面的安装 Node、安装依赖与构建步骤只适用于源码版。

## 1. 下载项目，准备好 Node.js

打开 [项目仓库](https://github.com/MewzCC/KleeAPI)，点击绿色的 **Code → Download ZIP**，下载后解压到你打算长期使用的文件夹。

打开解压后的目录，应该能看到 `package.json`、`frontend` 和 `Start-Manager.cmd`。后面的命令都在这个目录里执行。

电脑上还需要安装 **Node.js 22.12 或以上版本**。可以从 [Node.js 官网](https://nodejs.org/zh-cn/download) 下载安装包，npm 会一起安装。

安装后，重新打开终端，分别输入：

```powershell
node -v
npm -v
```

两条命令都能显示版本号，就可以继续。如果提示找不到命令，先关掉终端再打开；仍然不行，再检查 Node.js 是否安装成功。

如果你平时就用 Git，也可以这样下载：

```powershell
git clone https://github.com/MewzCC/KleeAPI.git
cd KleeAPI
```

## 2. 第一次启动

在项目文件夹的空白处右键，选择「在终端中打开」。确认终端当前所在的目录里有 `package.json`，然后依次执行下面三步。

先安装前端需要的依赖：

```powershell
npm run setup
```

这一步会下载依赖，等命令执行完，终端重新出现可以输入的位置后，再继续。

接着构建页面：

```powershell
npm run build
```

看到构建完成、没有报错后，启动服务：

```powershell
npm start
```

终端显示 `KleeAPI 已启动` 后，会自动打开管理页面。默认地址是：

[http://127.0.0.1:18887/admin](http://127.0.0.1:18887/admin)

这个终端正在运行服务，使用期间先不要关闭它。以后想放到后台运行，可以双击项目里的 `Start-Manager.cmd`；停止时双击 `Stop-Manager.cmd`。

`npm run setup` 通常只在第一次运行或依赖有变化时需要执行。首次构建完成后，日常打开项目直接启动即可。

如果 PowerShell 提示「无法加载 npm.ps1，因为在此系统上禁止运行脚本」，把命令里的 `npm` 换成 `npm.cmd`，例如：

```powershell
npm.cmd run setup
```

## 3. 先确认页面连上了本地服务

工作台的「首次接入」按连接账号、确认模型、测试消息、接入客户端显示进度。从向导打开其他页面时，顶部会显示进度、下一步和返回入口。在模型目录确认模型或成功复制 ID 后会回到向导。测试聊天收到回复后，关闭窗口即可回到向导继续接入。复制客户端配置后也会返回向导，方便你在自己的客户端收到回复后点「我已在客户端收到回复」。测试和客户端确认保留在当前页面会话，切换模型或 Key 后需要重新验证。

自动打开的页面会带入本机生成的 API Key。进入「统一网关」工作台，右侧的接入卡片里可以看到 Base URL 和完整 Key。

这里的 Key 可以直接编辑、复制，改完点击「保存并连接」才会生效。「连接设置」里也能修改同一个 Key。

想下次打开浏览器时继续使用，勾选「在此浏览器记住」后再保存。没有勾选时，Key 只保存在当前浏览器会话中。

如果你是手动输入地址打开页面，页面提示还没连接，可以从本机文件里找到相应的 Key，再填到「连接设置」中：

| 当前页面 | Key 文件，相对于项目目录 |
| --- | --- |
| 统一网关 | `Gateway-Chat/data/Gateway/api-key.txt` |
| WorkBuddy | `WorkBuddy-Chat/data/WorkBuddy/api-key.txt` |
| Trae | `Trae-Chat/data/Trae/api-key.txt` |
| Qoder | `Qoder-Chat/data/Qoder/api-key.txt` |

这些文件在第一次成功启动时生成。用记事本打开，复制里面的一整行即可，不要多带空格或换行。

每个平台有自己的 Key。给统一网关配置时用网关 Key，进入 Trae 页面时则用 Trae Key。通过页面左侧入口切换平台，已有的连接信息会一起带过去。

你也可以换成容易辨认的自定义值：以 `klee-` 开头，总长度为 8 到 256 个可见 ASCII 字符，不能包含空格。保存新 Key 后，已经接入的客户端也要跟着更新，否则还会拿旧 Key 请求。

工作台会明文显示完整 Key，发截图前请把这一栏遮住。

## 4. 添加一个你自己的平台账号

API Key 用来让客户端连接 KleeAPI。接下来还需要登录平台账号，才能读取这个账号可以使用的模型和额度。

先选你已经有账号的平台，例如 WorkBuddy：

1. 点击左侧的「WorkBuddy」。
2. 进入「账号管理」，点击「添加账号」。
3. 在「官方登录」区域选择账号对应的国内版或国际版。Trae 的区域已固定，无需另外选择。
4. 点击「官方登录」，在新打开的官方页面完成登录与授权。
5. 回到 KleeAPI，等待账号出现在列表里。

WorkBuddy 如果已经在这台电脑的官方桌面端登录，也可以点击「读取桌面登录」。

如果你已经有平台支持的账号凭据，可以展开「凭据 JSON」，粘贴凭据或选择 JSON 文件，再点击「导入账号」。凭据包含登录信息，自己保管即可，不要发到公开仓库或问题反馈里。

账号出现后，检查它是否处于启用状态。如果你准备直接调用某个平台，再把要使用的账号「设为当前」。通过统一网关调用时，网关会从已启用、授权有效且额度与模型可用的账号中调度。

第一次可以先添加一个账号，把后面的测试跑通，再慢慢加其他账号。

### Qoder 提示缺少官方组件时

Windows x64 上，如果没有安装 Qoder 官方桌面端或 CLI，使用国际版签到、对话时可能提示缺少身份组件。在项目目录执行：

```powershell
npm run setup:qoder
```

命令会下载并校验固定版本的官方包，把需要的组件放到本机 `runtime/qoder/`。完成后回到页面重试；仍然提示缺少组件时，停止服务再重新启动一次。

这个安装命令目前只支持 Windows x64。

## 5. 选一个模型，发出第一条消息

登录好账号后，点击左侧「统一网关」，进入「跨平台号池」，点击「刷新号池」。这里可以看到各平台账号是否可调度；如果账号暂不可用，先按页面给出的原因处理。

接着打开「模型目录」，点击「刷新模型」。模型按表格分页展示，可以搜索名称或 ID，也可以切换每页显示的条数。

找到要试的模型后，点击这一行的 **「用于 API 示例 →」**。页面会跳到「API 接入」，并填好对应的模型 ID。

在页面标题右侧点击 **「打开测试聊天」**，输入一句简单的话，例如：

> 你好，请用一句话介绍一下你自己。

点击「发送」。能正常收到回复，说明账号、Key、模型和调用地址已经连通。

测试会实际调用平台模型，可能消耗账号额度。打开窗口本身不会发出对话请求；只有点击「发送」才会调用。需要中断时点击「停止」，想重新开始可以「清空对话」。

测试窗口的对话历史保存在当前页面内存。经统一网关发出的测试消息遵循「记录与隐私」设置。关闭聊天窗口会停止正在进行的请求，切换模型会清空已有上下文。

如果你只想用某个平台，也可以直接进入它的「模型目录」和「API 接入」测试。

## 6. 接到自己的聊天客户端

在客户端里选择 **OpenAI 兼容接口 / Chat Completions**，填写这几项：

| 设置项 | 填什么 |
| --- | --- |
| Base URL / API 地址 | `http://127.0.0.1:18887/v1` |
| API Key | 从统一网关工作台复制的已保存 Key |
| 模型 ID | 从统一网关「模型目录」复制的完整 ID |

模型 ID 请直接复制，尤其要保留里面的平台、区域前缀。你在页面上看到什么，就填什么。

有些客户端要求填「完整请求地址」，这种情况填写：

```text
http://127.0.0.1:18887/v1/chat/completions
```

填写 Base URL 的地方只需要到 `/v1`。如果客户端会自动拼接 `/chat/completions`，就不要再手动加一遍。

通过统一网关调用时，客户端只需要网关 Key。如果想直连某个平台，地址和 Key 都换成对应平台的：

| 接入方式 | 默认 Base URL | 使用的 Key |
| --- | --- | --- |
| 统一网关 | `http://127.0.0.1:18887/v1` | 网关 Key |
| WorkBuddy | `http://127.0.0.1:18791/v1` | WorkBuddy Key |
| Trae | `http://127.0.0.1:17864/v1` | Trae Key |
| Qoder | `http://127.0.0.1:17865/v1` | Qoder Key |

这些地址供同一台电脑上的客户端使用。服务只监听本机，手机、其他电脑或独立容器里的 `127.0.0.1` 都不是这台电脑上的 KleeAPI。

需要 PowerShell、curl 示例，或想了解流式响应、工具调用等参数，可以继续看 [API 接入指南](API-GUIDE.md)。页面生成的示例使用 `klee-YOUR_API_KEY` 作为占位符，复制到自己的程序后记得替换。

## 平时怎么用

### 签到和查余额

「签到中心」可以刷新签到状态，也可以给单个账号、某个平台或全部账号领取奖励。刷新状态只查询，点击领取才会执行签到。

工作台上的「今日签到」会显示类似 `4/5` 的结果，表示 5 个账号里有 4 个已确认签到。停用账号和没有活动的账号也会计入总数，卡片下面会注明原因。Qoder 的活动按实际轮次显示，不一定按自然日重置。

余额可以在平台的「额度监控」里查看。统一网关的「跨平台号池」也会显示账号余额；有明确总额度时才显示剩余比例，总额未知时不会凭空算一个百分比。

「调用统计」用于看经过统一网关的请求、Token 和平台上报的积分消耗。平台没上报积分的请求会显示未上报，Token 数不会换算成积分。直接调用平台端口的请求不属于网关调用统计。

### 管理调用记录和对话原文

在「统一网关 → 调用统计 → 记录与隐私」选择「只记统计」或「保存原文」，再点「保存设置」。默认只记统计。改变保存方式只影响后续调用，已有原文仍可在相应记录的详情中查看。

保留期限可选不限天数、7 天、30 天或 90 天，最多保留最近 2000 条。缩短期限并确认保存后，过期的统计和原文会立即从本机清除。删除单条可在「调用详情」中操作。清空全部记录会清除所有统计和原文，包括当前筛选条件未显示的记录，并保留当前设置。

### 收起目录、切换主题

左侧导航栏可以折叠，给正文多留一点位置。主页面右侧隐藏了滚动条，鼠标滚轮、触控板和键盘仍然可以滚动；下方还有内容时，右下角会出现「下滑查看更多」，也可以直接点击它。

右上角「开启可莉主题」可以切换到粉色主题，关闭后恢复深色。外观选择会保存在浏览器里，通过页面入口切换平台时也会延续。

可莉主题右下角的旅行便笺里有「暂停装饰动效」。页面也会遵循系统的减少动态效果设置。素材来源和使用说明见 [主题说明](KLEE-THEME.md)。

### 停止服务

如果用 `npm start` 启动，在原来的终端里按 `Ctrl+C` 即可停止。

如果用启动脚本放到后台运行，双击 `Stop-Manager.cmd`，或者在项目目录打开另一个终端，执行：

```powershell
npm stop
```

关闭浏览器不会停止后台服务。想确认当前有没有运行，可以执行：

```powershell
npm run status
```

## 遇到问题时

### 页面打不开，或者提示无法连接本地服务

先确认启动命令没有报错，再运行 `npm run status` 查看服务状态。默认管理地址是 [http://127.0.0.1:18887/admin](http://127.0.0.1:18887/admin)。如果你改过端口，请使用修改后的地址。

如果只是浏览器没有自动打开，手动打开地址，再按前面的 Key 文件位置填写连接信息。

### 提示缺少前端文件

从 GitHub 下载的源码不包含编译后的页面。回到项目目录，先执行 `npm run setup`，再执行 `npm run build`，完成后重新启动。

### 提示端口被占用

可能是这个项目已经启动，也可能是其他程序使用了相同端口。先用 `npm run status` 检查本项目；如果已经运行，直接打开页面即可。

要换端口，修改根目录的 `klee-config.json`，再停止并重新启动。例如只把网关改到 `18888`，就修改 `gateway.port`。其他平台原来的配置可以保留。

每个平台的端口要互不相同，也不要使用 Trae 登录回调的 `18080`。开发模式另外使用 `15173`。

### 提示 API Key 无效，或者返回 401 / 403

到对应服务的工作台或「连接设置」里，重新填写并保存它当前的 Key。网关地址配网关 Key，平台地址配平台 Key。

刚换过 Key 的话，也检查一下聊天客户端是不是还在用旧值。复制时不要带上前后空格。

### 登录了账号，但模型目录为空或暂不可调用

先到账号管理检查：账号是否启用，授权是否过期，是否还有可用额度。平台直连还要确认当前选中了哪个账号。

处理好后，重新刷新网关号池和模型目录。切换账号或国内版、国际版后，也要重新确认模型 ID。具体模型能不能用，仍取决于账号权限和平台当前返回的结果。

### Trae 登录页打不开，提示回调端口不可用

Trae 官方网页登录使用 `18080` 端口。旧版本或其他程序占用了这个端口时，会影响新的网页登录。关闭占用它的程序后，停止并重新启动 KleeAPI，再试一次。

这不会影响其他平台，也不妨碍使用已有账号或导入凭据。项目不会替你结束占用端口的其他程序。

### Trae 签到提示 9074

先在这台电脑的 Trae 官方客户端里登录同一个账号，再回到「Trae → 账号管理」，对这个账号点击「同步本机设备」。同步成功后，再回签到中心核对状态或重试领取。

如果仍然被拒绝，到官方客户端查看活动和积分记录。页面只有复查确认签到后才显示成功，平台拒绝时不能保证奖励到账。

### 换电脑后，原来的账号打不开

Windows 下账号存储的加密密钥受当前用户的 DPAPI 保护。把文件夹搬到另一台电脑或另一个 Windows 用户下，原来的加密账号可能无法直接读取，需要重新登录或导入账号。

## 更新和本地文件

**便携版更新：** 先双击旧目录的 `Stop-Manager.cmd`，把新版 ZIP 完整解压到一个新目录。在同一电脑、同一 Windows 用户下，把下列四个 `*-Chat/data/` 文件夹和自己的 `klee-config.json` 复制到新版的对应位置，再双击新版的启动脚本。保留旧目录作为备份，不要把旧程序或 `runtime/manager.json` 覆盖到新版。换电脑或 Windows 用户时请重新登录。

**源码版更新：** 更新前先停止服务，再替换源码。如果你用 Git 下载，并且没有本地代码改动，可以在项目目录执行 `git pull`。接着重新安装依赖、构建和启动：

```powershell
npm run setup
npm run build
npm start
```

账号和 Key 保存在下面几个目录中，更新时请保留：

- `WorkBuddy-Chat/data/`
- `Trae-Chat/data/`
- `Qoder-Chat/data/`
- `Gateway-Chat/data/`

运行日志在 `runtime/logs/`。`runtime/manager.json` 是管理器的运行状态文件，包含本机关闭令牌，也不要公开分享。

遇到断电或强制关闭留下的管理器状态错误时，先确认对应进程已经退出，再处理遗留状态文件；正常停止请用 `npm stop` 或停止脚本。

账号、凭据和 Key 保存在本机，调用模型、登录和签到时会访问对应的平台服务。反馈问题时，只附上必要的报错，并遮住 Key、令牌和账号隐私信息。

## 想改代码的话

前端使用 Vue 3、TypeScript、Vite 和 Element Plus；后端是 Node.js。常用命令放在这里，方便查：

| 命令 | 用途 |
| --- | --- |
| `npm run setup` | 根据锁文件安装前端依赖 |
| `npm run build` | 检查类型并构建正式页面 |
| `npm run release:win` | 在 Windows x64 制作包含运行时、页面与组件许可证的便携 ZIP |
| `npm run release:verify` | 将正式 ZIP 解压到全新的中文空格路径，在无系统 Node/npm 的环境下验证启停 |
| `npm run dev` | 启动后端与前端开发页面，地址为 `http://127.0.0.1:15173/admin` |
| `npm run typecheck` | 检查 TypeScript 和 Vue 类型 |
| `npm test` | 运行使用模拟请求和临时数据的测试，不执行真实账号签到 |
| `npm run setup:qoder` | 安装 Windows x64 所需的 Qoder 官方身份组件 |
| `npm start -- --no-browser` | 启动服务，不自动打开浏览器 |

`frontend/` 是界面源码，`klee-api/app/` 是服务端公共逻辑，各平台适配器在 `klee-api/Klee-*-web/`，启动和停止相关脚本在 `scripts/`。

正式页面改完后执行 `npm run build`，刷新浏览器就能看到。后端代码改动需要重启服务。

源码仓库不包含 `node_modules`、`frontend/dist` 和便携的 `node.exe`。启动脚本会优先使用本机已有的 `runtime/node.exe`，否则使用系统安装的 Node.js。

`npm run release:win` 会根据锁文件安装前端构建依赖并构建，从官方固定地址下载 Node.js 24.22.2 LTS 和 Qoder 组件，通过校验后生成 `output/releases/KleeAPI-版本号-windows-x64.zip` 及同名 `.sha256`。首次打包需要联网，使用 Node.js 内置模块和 Windows 压缩能力，不需要额外安装打包工具。相同版本已有成品时拒绝覆盖，请先另存旧包或修改根 `package.json` 版本号。

成品只收集程序、静态页面、教程和组件许可；配置使用全新默认值，不读取本机账号和运行数据。包内 `release.json` 记录各文件校验值，启动时验证；`klee-config.json` 允许用户修改。`licenses/frontend/` 保存前端生产依赖许可证，`runtime/Node-SOURCE.json` 和 `runtime/qoder/source.json` 记录运行时来源。

GitHub Actions 的「Windows portable release」支持手动执行或推送与版本号一致的 `v版本号` 标签，构建后在无系统 Node/npm 的 PATH 下检查解压启动，再提供 ZIP 与 SHA-256 附件。工作流只上传干净成品，不上传测试启动后生成的目录，也不会自动发布 GitHub Release；发布者可将正式 ZIP 和校验文件作为 Release 附件上传。
