# 签到故障处理记录

## Qoder

本机存在历史配置，但没有可用的官方身份程序或 CLI 缓存。新增固定版本、SHA-512 校验的官方组件安装命令 `npm run setup:qoder`，并在客户端/CLI 查找之后补充本项目的本机安装目录。

实测国际版活动读取成功，领取 100 Credits 后复查 `checkedIn: true`；服务重启后 `/api/checkin` 返回 `status: already`。组件、DLL、来源记录和许可证保留在本机 `runtime/qoder/`，不进入 Git。

## Trae

对照本机官方客户端的 UG 请求，补充设备品牌、系统类型、系统版本、客户端版本；导入和网页登录保留这些字段。请求来源仍区分 IDE / SOLO，不通过切换来源或生成新设备来重试。

首次复测仍返回 `trae_9074`。用户确认已登录同一账号后，发现本地适配只识别明文记录，未支持官方 tc05 加密格式，因此没有取得当前设备绑定。同时，该账号保存的是网页登录来源 2，而实际已登录的官方客户端来源为 IDE 1。

新增 tc05 格式解码和明文完整性校验，仅返回账号标识及范围，不返回令牌。确认当前同一账号后，使用真实官方客户端设备与来源实测领取 100 积分，复查已签到。通过新增的设备同步接口保存该账号的正确绑定，原访问令牌、刷新令牌和当前账号均保持不变；重启后的服务也确认已签到。

账号页新增「同步本机设备」，对应受服务 Key 保护的 `POST /api/accounts/:uid/device`。该操作只保存设备白名单字段；正常签到不枚举来源。历史设备密钥和不明身份不能证明当前账号。独立审查发现的历史账号残留绑定与并发令牌刷新覆盖设备问题均通过失败回归用例修复。
