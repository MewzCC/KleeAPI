# KleeAPI

把 WorkBuddy、Trae、Qoder 的账号放到一个本地页面里管理，再通过同一个 API 地址调用它们的模型。

如果你平时在几个平台之间来回切换，KleeAPI 可以帮你把账号登录、签到、余额和模型接入放到一起。浏览器里能完成日常管理，也能直接打开测试聊天，确认模型可以使用后，再接到自己的客户端。

第一次使用，请从 **[使用教程](docs/TUTORIAL.md)** 开始。里面从下载安装、启动服务讲起，一步步带你连接账号、配置 Key，再发出第一条测试消息。

## 可以做什么

| 功能 | 说明 |
| --- | --- |
| 账号管理 | 分别管理 WorkBuddy、Trae、Qoder 账号，支持官方登录、凭据导入、启用与停用、切换当前账号。WorkBuddy 还可以读取本机桌面端登录。 |
| 统一网关 | 给客户端配置一组网关地址和 Key，调用不同平台的模型；根据账号的授权、额度和模型可用情况进行调度。也可以使用各平台自己的接口直连。 |
| 模型目录 | 浏览账号实际可用的模型，按名称或 ID 搜索、分页查看，复制完整 ID，或直接带入 API 示例。 |
| 签到与额度 | 查询签到结果，为指定账号、某个平台或全部账号领取奖励，查看余额及平台返回的额度明细。 |
| 调用统计 | 查看经过网关的调用记录、趋势、Token 和平台上报的积分消耗。缺失的积分数据会标为未上报。 |
| API 接入 | 在页面中生成请求示例，打开测试聊天验证配置。支持 OpenAI 兼容的 Chat Completions 格式，具体能力取决于平台和模型。 |

工作台可以直接查看和编辑当前服务的完整 API Key，保存后与「连接设置」同步。页面提供深色和可莉两种外观，左侧目录可以折叠，窄屏下也能使用。

## 网关和平台页面怎么分工

「统一网关」用于汇总各平台账号、查看可调度状态，并向客户端提供统一的模型入口。客户端通过它接入时，只需要使用网关 Key。

WorkBuddy、Trae、Qoder 各自的页面负责管理对应平台的登录、账号、签到和额度。如果你只用一个平台，也可以直接使用它的 API 地址和 Key。

默认管理入口是 [http://127.0.0.1:18887/admin](http://127.0.0.1:18887/admin)，网关 Base URL 是 `http://127.0.0.1:18887/v1`。服务启动后，在页面里可以复制实际使用的地址和模型 ID。

## 运行环境和数据

项目需要 **Node.js 22.12 或以上版本**和 npm。[使用教程](docs/TUTORIAL.md) 按 Windows 编写，仓库提供双击启动与停止脚本。源码不包含依赖、编译后的页面和便携 Node，第一次运行需要先安装依赖并构建。

账号和 Key 保存在本机的各平台数据目录中。服务只监听本机回环地址，适合同一台电脑上的客户端接入；登录、签到和模型调用会访问对应的平台服务。模型权限、可用额度与调用限制仍由平台和账号决定。

Windows 下账号存储的加密密钥受当前用户的 DPAPI 保护。换电脑或换 Windows 用户时，原来的加密账号可能无法直接读取。更新、保留数据和重新接入的说明见 [使用教程](docs/TUTORIAL.md#更新和本地文件)。

工作台会明文显示完整 Key。分享截图、日志或反馈问题前，请遮住 Key、令牌和账号隐私信息。

## 代码在哪里

前端使用 Vue 3、TypeScript、Vite 和 Element Plus，后端使用 Node.js。

```text
frontend/              管理页面
klee-api/app/          本地 API、账号存储和统一网关
klee-api/Klee-*-web/   各平台适配器
scripts/               启动管理器和组件安装脚本
docs/                  教程、接口与来源说明
```

开发模式、构建和测试命令放在 [教程末尾](docs/TUTORIAL.md#想改代码的话)。
